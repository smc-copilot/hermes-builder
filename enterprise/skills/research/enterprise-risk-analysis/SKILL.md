# 企业风险系统性分析与信用评级技能

## 适用场景

当用户请求对一家公司进行系统性风险评估或信用评级时触发。典型触发形式：

- **"请为XX公司做风险评估"**
- **"分析XX公司的业务风险和财务风险"**
- **"XX公司信用评级分析"**
- "请从资金面和业务面分析XX公司的风险"
- "为XX公司做一份全面的风险评估报告"

## 十一维度评估框架

### 维度总览

| # | 维度 | 核心问题 | 关键检索目标 |
|---|------|---------|-------------|
| 1 | **企业基本画像** | 公司是谁？规模多大？行业地位如何？ | 注册资本、员工规模、技术实力、年营收、行业地位、主营业务 |
| 2 | **财务状况与偿债能力** | 钱够不够？盈利好不好？债务重不重？ | 注册资本实缴率、资产负债率、纳税信用等级、毛利率、净利率、经营现金流 |
| 3 | **合规与信用审查** | 有没有官司？有无失信记录？ | 失信被执行人、司法冻结/查封、注销/吊销风险、立案信息、诉讼数量、行政处罚、经营异常、制裁清单、实控人涉案风险 |
| 4 | **运营效率** | 资金转得快不快？库存积不积压？ | 应收账款周转天数、库存周转率、评估其健康状态 |
| 5 | **公司治理与资本运作** | 治理稳不稳？融资能力强不强？ | 法人代表变更、融资能力、对外担保、大额投资并购、债转股 |
| 6 | **行业环境与宏观风险** | 赛道是上行还是下行？有无政策压制？ | 行业周期位置、政策抑制（去产能/贸易关税）、技术变革威胁、市场健康度 |
| 7 | **供应链与合作伙伴风险** | 上下游稳不稳？有无利益冲突？ | 核心供应商、重要客户、利益冲突、合作伙伴重大风险 |
| 8 | **舆情与声誉风险** | 有没有重大负面事件？ | 重大质量事故、重大投诉、产品召回、重大舆情事件 |
| 9 | **综合风险矩阵与雷达图** | 各维度风险如何可视化？ | 综合风险矩阵（概率×影响）、风险雷达图（8维度评分）、情景推演 |
| 10 | **三等九级信用评级** | 综合信用等级是什么？ | AAA/AA/A/BBB/BB/B/CCC/CC/C |
| 11 | **风险评估报告输出** | 如何结构化呈现？ | 核心摘要→基本状况→财务偿债→合规信用→行业宏观→综合评级与授信建议 |

## 三等九级信用评级体系

采用国内评级机构通用标准：

| 等级 | 含义 | 偿债能力 | 违约风险 |
|------|------|---------|---------|
| **AAA** | 最高级 | 极强 | 极低 |
| **AA** | 高级 | 很强 | 很低 |
| **A** | 中上级 | 较强 | 较低 |
| **BBB** | 中级 | 一般 | 一般 |
| **BB** | 中下级 | 较弱 | 较高 |
| **B** | 下级 | 较差 | 很高 |
| **CCC** | 投机级 | 很差 | 极高 |
| **CC** | 高度投机级 | 严重不足 | 极大 |
| **C** | 违约级 | 基本不能偿还 | 确定违约 |

每个等级可加"+"或"-"表示微调（如AA+、A-），表示在该等级中偏上或偏下。

### 评级映射规则

基于11维度综合评分（每个维度1-10分，总分归一化后映射）：

| 综合得分 | 对应等级 |
|---------|---------|
| 90-100 | AAA |
| 80-89 | AA |
| 70-79 | A |
| 60-69 | BBB |
| 50-59 | BB |
| 40-49 | B |
| 30-39 | CCC |
| 20-29 | CC |
| 0-19 | C |

## 搜索工具偏好与故障回退协议

### 首选搜索工具：百度搜索API

本skill所有web检索**必须优先使用百度搜索引擎**。百度对中国企业信息（企查查/爱企查/启信宝/天眼查/裁判文书网等）的索引覆盖率和snippet信息密度显著优于通用搜索引擎（Google/Bing/DuckDuckGo）。

**实现方式**：所有搜索轮次使用 `web_search` 工具，并附加百度搜索引擎限定。搜索策略如下：

```
# 标准百度搜索调用格式
web_search("{关键词}")  # 系统默认配置百度为搜索后端
```

**注意**：具体调用语法取决于当前Hermes环境的 `web_search` 后端配置。如环境已配置百度为搜索引擎后端，直接使用 `web_search()` 即可；若未配置，需在首次调用前确认。

### 故障检测与回退协议

> ⚠️ **铁律**：百度搜索出现故障时，**禁止自动切换到备用搜索引擎**。必须暂停分析流程，主动与用户沟通。

#### 故障判定标准

以下任一情况视为百度搜索故障：

| 故障类型 | 判定条件 |
|---------|---------|
| 连接失败 | `web_search` 返回连接超时、DNS解析失败、HTTP 5xx |
| 空结果 | 连续3轮搜索返回0条结果（非正常"搜不到"的情况） |
| 结果质量异常 | 搜索结果与查询关键词完全不相关（疑似后端切换） |
| 速率限制 | 返回429或 rate limit 错误 |

#### 故障处理流程

```
百度搜索故障
    ↓
立即暂停所有搜索操作
    ↓
向用户发出明确提示：
  "⚠️ 百度搜索API当前不可用（原因：{具体错误}）。
   是否切换到备用搜索引擎（{可用备选}）继续分析？
   - 选择"是"：我将使用备用引擎完成剩余搜索
   - 选择"否"：我将中止分析，等待百度API恢复"
    ↓
等待用户明确回复后，按用户决定执行
    ↓
在报告中标注哪些搜索结果来自备用引擎（如适用）
```

#### 备用搜索引擎

当用户授权切换时，按以下优先级使用备用引擎：
1. **Bing**（对中国企业信息覆盖次优）
2. **Google**（适合上市公司/国际业务信息）
3. **DuckDuckGo**（隐私优先，但中文企业信息覆盖有限）

> 使用备用引擎时，每次搜索调用后必须在脑内标注 `[备用引擎: {引擎名}]`，并在最终报告的「数据来源清单」中明确区分百度来源与非百度来源。

## 完整工作流程（12步）

> **搜索工具说明**：以下所有搜索轮次中的代码块均为**概念性调用示例**。实际执行时，所有检索统一使用百度搜索引擎（通过 `web_search(query="...")` 执行，后端已配置为百度）。如百度出现故障，严格按照上述「故障检测与回退协议」处理，不得自动切换。

### 第1轮搜索（并行）：企业基本画像

```bash
web_search(query="{公司名} 公司概况 注册资本 股东 创始人 主营业务")
web_search(query="{公司名} 营收 员工规模 行业地位 技术实力")
web_search(query="{公司名} 融资 估值 上市 IPO")
```

**提取目标**：
- 工商信息：注册资本、成立日期、法定代表人、注册地址
- 股权结构：主要股东及持股比例
- 企业规模：员工数量、分支机构
- 经营状况：年营收（如有披露）、主营业务与产品线
- 行业地位：市场份额、排名、技术资质/专利

---

### 第2轮搜索（并行）：财务与偿债能力

```bash
web_search(query="{公司名} 注册资本 实缴 资产负债率 纳税信用等级")
web_search(query="{公司名} 毛利率 净利率 经营现金流 财务数据")
web_search(query="{公司名} 年报 财报 审计报告")  # 上市公司优先查巨潮/SEC/港交所披露易
```

**提取目标**：
- 注册资本实缴率（实缴资本/注册资本）
- 资产负债率（如有财报数据）
- 纳税信用等级（A/B/C/D级）
- 毛利率、净利率
- 经营现金流正负及趋势
- **3年财务对比（NEW）**：对于上市公司，**必须检索最近3个完整财年**的营收、毛利率、净利率、ROE、资产负债率，建立财务趋势判断。例如仅看到FY2024下滑7.4%可能误判为下行，但FY2025增长18.6%则表明行业已反转。3年数据才能呈现完整轨迹。
- **核心财务比率（NEW，上市公司强制）**：上市公司必须尽量获取以下精确指标：
  - ROE（净资产收益率）
  - 净现金头寸（现金及等价物 - 有息负债）
  - 每股收益（EPS）
  - 自由现金流
  - 利息保障倍数（如有）
- **上市公司**：优先查阅巨潮资讯/SEC EDGAR/港交所披露易官方财报
- **台湾上市公司（TWSE）**：查台湾证券交易所公开资讯观测站（mops.twse.com.tw）、公司官网投资者关系页面（通常有PDF年报）、Yahoo Finance Taiwan、Simply Wall St、WSJ Market Data、Bloomberg、GuruFocus。TWSE公司通常披露完整的合并财报（含资产负债表、损益表、现金流量表），搜索时优先用英文品牌名 + "annual report" + 年份，或上市代码+"financial statements"
- **非上市公司**：标注"公开数据不足"，基于媒体报道间接推断

---

### 第3轮搜索（并行）：合规与信用审查

```bash
web_search(query="{公司名} 失信 被执行人 司法冻结 查封")
web_search(query="{公司名} 诉讼 立案 行政处罚 经营异常")
web_search(query="{公司名} 注销 吊销 制裁 实控人 涉案")
```

**提取目标**：
- 失信被执行人记录
- 被执行案件（数量、金额）
- 司法冻结/查封记录
- 注销/吊销风险（含关联企业）
- 立案信息、诉讼案件数量与类型（劳动争议/合同纠纷/知识产权）
- 行政处罚记录
- 经营异常列入记录
- 制裁清单（SDN清单、实体清单等）
- 实控人/董监高涉案风险

---

### 第4轮搜索（并行）：运营效率

```bash
web_search(query="{公司名} 应收账款 周转天数 账期")
web_search(query="{公司名} 库存周转 存货周转率 库存积压")
```

**提取目标**：
- 应收账款周转天数（DSO，Days Sales Outstanding）
- 库存周转率（Inventory Turnover）
- 与行业平均水平对比
- 评估状态：健康 / 关注 / 预警 / 严重

**评估标准**：

| 指标 | 健康 | 关注 | 预警 | 严重 |
|------|------|------|------|------|
| DSO（天） | <60 | 60-90 | 90-180 | >180 |
| 库存周转率（次/年） | >6 | 4-6 | 2-4 | <2 |

注意：不同行业标准差异大，需结合行业特性调整。

---

### 第5轮搜索（并行）：公司治理与资本运作

```bash
web_search(query="{公司名} 法人代表 变更 董事长 总经理 高管变动")
web_search(query="{公司名} 融资能力 对外担保 对外投资 并购")
web_search(query="{公司名} 债转股 股权质押 股权冻结")
```

**提取目标**：
- 法人代表/董事长/总经理近期（2年内）变更情况
- 融资能力：最近一轮融资时间与金额、投资方背景
- 对外担保：担保总额占净资产比例
- 大额对外投资/并购活动
- 债转股情况
- 股权质押比例

---

### 第6轮搜索（并行）：行业环境与宏观风险

```bash
web_search(query="{行业名} 行业周期 2025 2026 发展趋势 增速")
web_search(query="{行业名} 政策 监管 去产能 贸易关税 限制")
web_search(query="{行业名} 技术变革 颠覆性创新 技术替代")
```

**提取目标**：
- 行业生命周期位置：导入期/成长期/成熟期/衰退期
- 行业增速（近2年数据）
- 政策环境：鼓励/中性/抑制/强管制
- 具体政策风险：去产能、贸易关税、出口管制、环保限制
- 技术变革威胁：是否存在颠覆性技术替代
- 市场健康度：供需关系、价格走势、行业集中度（CR5/CR10）

---

### 第7轮搜索（并行）：供应链与供应链金融风险评估（含采购深度）

```bash
web_search(query="{公司名} 供应商 核心供应商 供应链 采购")
web_search(query="{公司名} 客户 核心客户 大客户 合作方")
web_search(query="{公司名} 利益冲突 客户重叠 竞争关系 合作方风险")
```

**提取目标**：
- 核心供应商名单及集中度（前5大供应商占比）
- 重要客户名单及集中度（前5大客户占比）
- 客户-供应商重叠问题
- 是否存在与客户的竞争关系（品牌-代工冲突等）
- 合作伙伴重大风险（供应商破产/客户流失/断供风险）

#### 7a. 制造型客户的供应链采购深度评估（NEW，强制步骤）

> 对于**制造型客户**（电子/工业/汽车等），除上述基础供应商分析外，必须额外评估以下采购维度：

| 评估维度 | 搜索方法 | 评估标准 |
|---------|---------|---------|
| **年元器件采购规模** | 基于营收×COGS占比(60-70%)估算 | 规模大小直接影响合作价值 |
| **COGS（营业成本）** | `[公司名] 年报 营业成本 cost of revenue` | 上市公司可精确查到 |
| **核心元器件品类依赖度** | 从产品线反推 | CPU/SoC/存储/模拟等各品类依赖程度 |
| **供应链区域集中度** | 制造基地分布分析 | 单一区域占比过高有断供风险 |
| **美国技术依赖度（NEW）** | 分析核心芯片的美国原产比例 | 对出口管制敏感性评估的关键输入 |
| **供应商替换成本** | 评估各品类替代难度 | BOM验证周期、认证成本 |

**输出到报告**：在第八章「供应链与合作伙伴风险」中新增子节分析上述维度。

---

### 第8轮搜索（并行）：舆情与声誉风险

```bash
web_search(query="{公司名} 质量事故 投诉 召回 维权")
web_search(query="{公司名} 舆情 负面 争议 丑闻 315")
web_search(query="{公司名} 安全事故 环境事故 劳动纠纷 集体诉讼")
```

**提取目标**：
- 重大质量事故记录（近3年）
- 重大投诉/集体维权事件
- 产品召回记录
- 重大舆情事件（近2年热点）
- 安全事故/环境事故
- 劳动纠纷/集体诉讼

> ⚠️ **IoT/工业科技公司的产品安全漏洞（CVE）子维度**：
>
> 对于物联网/工业计算/嵌入式类公司（如研华科技、西门子等），产品安全漏洞是独特的声誉风险来源，应在舆情声誉维度中单独评估：
>
> 1. **主动搜索**：添加 `"{品牌名}" CVE 漏洞 安全 通报` 或 `"{品牌名}" vulnerability CVE` 到搜索组合
> 2. **评估维度**：
>    - CVE数量与严重程度（CVSS评分分布）
>    - 是否涉及CVSS 9.0+的严重漏洞
>    - 漏洞发现后厂商的响应速度与补丁覆盖
>    - 是否被国家级网络安全机构（如CSA新加坡、CISA美国、CNVD中国）发布安全警报
> 3. **报告呈现**：在舆情声誉章节单独列出一节「产品安全漏洞」，列出近2年主要CVE及其影响

- `/data/hermes/skills/productivity/markdown-conversion/scripts/md2docx.py`

## 关键原则

### 数据纪律

1. **双源交叉验证**：每个关键数据至少标注一个可追溯来源
2. **区分事实与推论**：同上
3. **时效性标注**：同上
4. **AI幻觉抑制**：同上
5. **非上市公司特殊处理**：同上

### 非上市SME搜索策略（Pitfall）

> ⚠️ **非上市中小企业的公开数据极度碎片化**。企查查/爱企查/启信宝的详细数据（裁判文书全文、精确财务指标、股东持股比例）均在付费墙之后。但搜索摘要（snippet）中经常泄露关键信息：
>
> - **爱企查snippet常泄露**：参保人数、法定代表人兼任职务、知识产权数量汇总（专利/商标/软著）、资质认定列表
> - **企查查snippet常泄露**：资质荣誉标签（如"国家级专精特新小巨人"）、法律诉讼栏目入口
> - **启信宝snippet常泄露**：投融资轮次数、知识产权出质数量、对外投资数量
> - **百度百科/官网/Gitee**：公司定位描述、合作伙伴名单、产品线信息
>
> **策略**：对非上市SME执行6-8轮并行搜索（每轮3条），覆盖[工商画像/财务推断/合规审查/行业定位/合作伙伴/舆情]六个维度，从snippet中拼凑完整画面。不要期望单次搜索获取完整数据。
6. **搜索结果的实体消歧**（NEW）：当搜索关键词与多家公司品牌名/简称重叠时，务必识别搜索结果指向的是否为目标公司。例如搜索"Advantech" + "lawsuit" 可能会返回"Advantech/Prime"（一家美国投资基金的诉讼），而非台湾研华科技。应：
   - 打开结果链接阅读内容确认实体身份
   - 在报告中注明"经核实非目标公司"并排除
   - 误报型结果不纳入风险评估
   - 如果误报频繁降低搜索精度，添加目标公司股票代码或国家限定词（如"TWSE:2395"或"台湾"）
3. **时效性标注**：价格、政策、排名等时间敏感信息标注采集时间
4. **AI幻觉抑制**：不编造财务数据、市场份额、估值。非上市公司财务数据不透明时声明"公开数据不足，以下为基于间接信息的推断"
5. **非上市公司特殊处理**：
   - 利润率、资产负债率、应收账款周转率等通常无法获取
   - 标注"⚠️ 公开数据不足"的数据缺口
   - 纳税信用等级可通过国家税务总局官网或第三方平台查询
   - **必须在报告末尾添加"尽职调查缺口"小节**，列出贷前/投前必须实地核实的缺失数据
   - 不可得数据维度保守评分（偏低处理）

### 风险判断纪律

1. **保守取向**：不确定时，偏向于标注为更高风险等级而非更低
2. **情景推演标注**：明确说明是压力测试而非预测
3. **不构成建议**：声明所有分析仅供参考，不构成投资或决策建议

### 评级纪律

1. 评级基于已完成检索的可验证数据
2. 数据缺失的维度保守处理（偏低评分）
3. 评级展望（稳定/正面/负面）需明确标注依据
4. 与行业平均水平的比较需有数据支撑

7. **web_extract工具局限性**（Pitfall）：`web_extract` 工具在默认DuckDuckGo后端下不可用（报错"search-only backend"），需要配置firecrawl/tavily/exa/parallel后端才能工作。对于中国企业信息页面（爱企查/企查查/启信宝），即使后端可用，这些页面多为JavaScript动态渲染，提取效果不佳。**替代方案**：优先从搜索snippet中提取关键数据点，辅以多轮定向搜索拼凑完整信息，不要依赖web_extract作为主要数据获取手段。

## 滚动再评估（对已评估过的公司）

> 当目标公司**此前已出过风险报告**（检索 memory / Obsidian `企业研究/{公司}/风险评估/` / 技能 references 案例复盘可发现基线），不要从零重做，按增量更新：

> 2. **只查 delta**：优先检索上期报告日之后的新事件（司法/融资/并购/舆情/监管），而非重复全量11维度搜索。
> 3. **量化变化**：在新报告 frontmatter 加 `prior_rating` 字段，正文核心摘要写明"较上期 X→Y、原因"。
> 4. **评级纪律——或有vs兑现**：若上期标注的"或有/待完成"风险本期落地，即使方向已知，也应据"确定性上升+现金/资产已投入"重估（通常微降半档并维持负面观察），而非因"靴子落地不确定性消除"而上调。真正的拐点看**先行指标**（如大客户是否转单、被收购方亏损收窄斜率），设为月度硬监控。
