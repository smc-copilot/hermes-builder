# 独立分销优势品牌应用领域字典（Distributor Advantage Brand Dictionary）

独立分销业务场景下，35 个优势品牌的业务版图数据资产。与 `authorized-product-line-reference`（**授权代理**品牌×品类矩阵）互补，本字典记录的是**独立分销/混合分销覆盖的优势品牌**（含非授权品牌），供业务分析类 skill 调用做品牌版图查询、品类反查与业务机会匹配。

## 定位与边界

| 做（Do） | 不做（Don't） |
|---------|--------------|
| 提供品牌→细分品类/应用/定位/产能/排名查询 | 不做客户分析、不产出报告（那是调用方的事） |
| 提供品类→品牌反查（哪些品牌能做某品类） | 不推断具体客户需求、不评估交易质量 |
| 提供定位速查总索引（高/中/低端分层） | 不擅自增删品牌（须用户/业务方确认） |
| 维护数据版本与变更记录 | 不做市场/行业趋势预测 |

> **与授权品牌数据的区别**：`authorized-product-line-reference` 记录的是**已签授权代理协议**的品牌；本字典记录的是**独立分销/混合分销可覆盖的优势品牌**，两者可能重叠但不互为派生。调用方须区分"授权代理"与"独立分销覆盖"两种表述。


调用方注意事项：
1. **不缓存**：每次任务实时加载，确保使用最新版本（版本见"数据版本与变更记录"）
2. **引用标注**：报告引用品牌版图结论时，标注数据源"独立分销优势品牌字典 vX.X"
3. **异常处理**：加载失败（skill 不存在/返回异常）时，停止依赖该数据的步骤，标注"独立分销优势品牌字典不可用"，不得凭记忆编造品牌/品类/排名关系
4. **授权 vs 独立分销区分**：本字典为**独立分销/混合分销覆盖**品牌，与 `authorized-product-line-reference` 的**授权代理**品牌须分开表述；材料中出现但两表都没有的品牌 ≠ 不可供应，标注"渠道待确认"交由业务确认

### 报告体现约定（集成方必读）

当画像/客户群分析类 skill（customer-profiling、sales-rep-portfolio-analysis、sales-team-portfolio-analysis 等）集成本字典做品牌匹配时，报告中的匹配结果遵循以下约定：

1. **双源分列、不混写**：品牌推荐结果拆为「推荐品牌（授权）」与「推荐品牌（独立分销）」两列（或两个并列字段），独立分销来源一律标「独立分销」标签。严禁把授权品牌与独立分销品牌混写在同一列——销售团队会混淆"已授权代理"与"独立分销覆盖"两种供货身份，导致报价/账期/合规口径出错。
2. **定位分层筛选**：用"定位速查总索引"结合客户的价格/技术定位筛选同档位品牌优先推荐，避免给低端客户推高端品牌（或反之）。
3. **按需加载时机**：仅在"品牌匹配/机会评估"阶段 `skill_view` 加载本字典，不在搜索/产品识别阶段加载，避免无关上下文消耗。
4. **匹配结果可追溯**：报告中独立分销品牌推荐须能追溯到字典的"品类→品牌反查表"或某批次 references 明细，标注字典版本号。

| 定位判断调整 | 某品牌因产品升级/降级需调整定位层级 |
| 品牌归属变化 | 并购/剥离（如 Xilinx 并入 AMD） |

## 新增批次/品牌研究工作流（扩展字典时执行）

> 当用户要求新增一批品牌（如"第四批""再补充 XX 品牌"）时，按此流程逐品牌检索并回填本字典。**本字典是数据资产，但扩展它的研究工作流固化于此，避免每次重新摸索。**

### 搜索方法（用户强制偏好）

1. **单智能体、单次并发**：一次只发一个 `web_search`，绝不并行批量搜索。这是用户明确要求（"单每个智能体只允许1次并发"），也是避免百度 API 限流的关键。逐品牌顺序推进。
2. **后端**：`web_search` 已配置百度搜索 API 后端（`web.search_backend: baidu-search`），直接调用即可。
3. **每品牌一个针对性 query**：`[品牌名] 产品线 细分品类 应用领域 [特色关键词] 排名 市场份额`。注意补充品牌别名（如"美台"=Diodes、"立锜"=Richtek、"强茂"=PANJIT）。小厂（非上市）可能一次检索信息不足，需二次针对性检索补全细分品类。
4. **每品牌一次检索通常够用**；排名/份额数据不清晰的品牌可补充一次针对排名/产能的检索。用 todo 清单跟踪逐品牌进度。

### 三项信息结构（用户明确要求）

每品牌必须收集齐全三项，缺一不可：
1. **芯片细分品类**：尽量收集齐全，用表格按"大类/细分类别"两列展开。
2. **主要应用电子产品**：列举终端电子产品/行业，不是泛泛的市场叙事。
3. **市场定位（高/中/低端）+ 产能供给 + 排名**：定位是相对判断（结合单价/技术壁垒/应用场景）；排名分**全球/领域/区域**三级标注；产能多数原厂不公开精确数字，用"IDM/Fabless 模式 + 公开扩产/营收公告"做定性表述。

### 搜索/整理陷阱（务必注意）

1. **名单重复检测**：开始检索前先核对新名单与既有批次是否重复（本任务第二批曾误粘贴成第一批，已 clarify 暂停）。发现重复或疑似错误先向用户确认，不盲目执行。
2. **跨境/台资归属如实标注**：安世（闻泰控股/荷兰总部）、Richtek（联发科旗下/中国台湾）、强茂（中国台湾）等，按用户归类入批次但须标注真实归属。
3. **并购品牌状态**：Cypress→英飞凌、Xilinx→AMD、Altera→银湖资本（51%）/英特尔（49%），保留品牌线但标注"已并入母体，供分销按历史型号识别"。
4. **双主体品牌**：Samsung 存储（DRAM/NAND/eMMC）属**三星电子**，MLCC 属**三星电机 SEMCO**，是两个主体，须分列。
5. **非芯片品类表述调整**：连接器（TE/Molex/Amphenol）、被动器件（Murata/SEMCO）不是芯片，表格列名从"芯片细分品类"改为"产品细分品类"，避免术语错误。
6. **非上市/小厂数据稀疏**：瑞斯特、仁懋、晶导微等非上市厂商公开数据少，产品线以官网/第三方代理资料为准，排名只能定性判断，须在局限性声明标注[数据缺口]。
7. **排名口径差异**：市场份额因机构（TrendForce/Counterpoint/Yole/Omdia/TSR 等）与年份不同而异，标注"约"及年份/口径区间，不写死单一数字。
8. **数据时效**：存储（DRAM/NAND/NOR）正处涨价周期，排名/价格变化快，标注采集日期并建议按月/季度刷新。

### 更新流程

1. 用户/业务方提出变更请求（明确：品牌/品类/应用/定位/排名/依据）
2. 修改本 skill 的 SKILL.md 对应表格（总览表/定位索引/反查表）
3. **同步修改 references/ 对应批次明细文件**（总览表与明细不一致视为数据缺陷）
4. 在"数据版本与变更记录"追加一行（版本号 +1、日期、变更说明）
5. 向用户报告变更摘要（改了什么表、影响哪些调用方）

### 数据准确性纪律

- 排名/份额以权威机构（TrendForce/Counterpoint/Yole/Omdia/WSTS/TSR 等）为准，标注年份与口径
- 不确定的数据标注"待确认"，不得猜测
- 产能数据多数原厂未公开精确数字，采用"IDM/Fabless 模式 + 公开扩产/营收公告"的定性表述，不编造精确产能
- 定位层级为相对判断，调整须说明理由
