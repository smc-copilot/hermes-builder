# Skill 编写命名规范（从 semiconductor-marketing-copy 习得）

## 章节标题：慎用"陷阱"

### 问题

在 skill 中为常见问题和规避措施建章节时，容易惯性使用"陷阱 (Pitfalls)"作为标题。

**"陷阱"的语义偏差**：
- "陷阱"隐含**隐蔽性**——你不知道那里有个坑，掉进去才发现。适用于真正的技术盲区（如"后缀变体混淆""SPN料号未映射"）。
- 很多条目实际是**执行纪律问题**——你知道该做但可能偷懒跳过（如"百度API故障别擅自切引擎""别忘了输出docx"）。
- 将两类问题统一标为"陷阱"，对执行纪律类条目不恰当——用"注意事项"式标题做"陷阱"格式的条目，"有违常识"。

### 规范

使用以下命名体系：

```
## 常见问题与规避

### 问题1：技术盲区类问题
### 问题2：执行纪律类问题
### 问题3：...
```

- **章节标题**：`## 常见问题与规避`（不再使用 `Pitfalls` 或 `常见陷阱`）
- **条目标题**：`### 问题N：具体问题描述`
- **每个条目内部**：仍使用 `**问题**：` 和 `**规避**：` 子结构

"问题"是中性词——覆盖隐蔽性技术盲区 + 执行纪律缺失两类，不预设"你不知道"还是"你偷懒"。

### 适用范围

本规范适用于所有 Hermes skill 的编写。已在以下 skill 中实践：
- `semiconductor-marketing-copy` v2.0.0（16条问题，含技术盲区和执行纪律）
- `b2b-contact-finder` 的"常见陷阱与经验"节可参照迁移

### 反面示例

```
## Pitfalls（常见陷阱与规避）     ← 不应使用，有语义偏差
### 陷阱15：百度API故障时自行切换备选引擎  ← 这是执行纪律，不是隐蔽陷阱
```

### 正面示例

```
## 常见问题与规避
### 问题15：百度API故障时自行切换备选引擎
**问题**：百度搜索API故障时，写作者未经用户授权即自动切换到DuckDuckGo...
**规避**：严格遵守"百度API故障降级协议"...
```
