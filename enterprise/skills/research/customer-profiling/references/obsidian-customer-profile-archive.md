# Obsidian 客户画像知识库归档工作流

> **实战验证**：2026-08-10，20 份客户画像报告统一归档（17 新增 + 3 重命名 + 去重 3 组）。
> **适用**：画像报告生成后归档到 Obsidian 库、客户状态管理（待开发/已合作）。

---

## 一、目标目录与命名规范

| 项 | 规范 |
|----|------|
| 归档目录 | `/data/hermes/obsidian-vault/客户画像/` |
| 命名规范 | `YYYYMMDD_公司简称_客户画像报告.md`（与 exports 一致） |
| 索引文件 | `README_索引.md`（含状态列 + wikilink 引用名单） |
| 状态名单 | `待开发客户名单.md`（待开发客户管理） |
| 双格式 | .docx 保留在 `/data/hermes/workspace/exports/`，Obsidian 库仅存 .md |

## 二、五步归档流程

### 第 1 步：全源盘点
- 搜索范围：`exports/`、`drafts/`、workspace 根目录、Obsidian 库全部目录
- 搜索模式：`*画像*`（文件名）+ 内容含「客户画像」（捕捉命名不统一的文件，如「杉川机器人_客户画像.md」「电子元器件和集成电路国际交易中心_客户画像报告.md」）
- 特别注意：早期报告可能用公司全称命名、无日期前缀、或放在 workspace 根目录

### 第 2 步：md5 去重与版本裁决
同客户存在多个版本时（如蓝之洋：exports 20260803 版 vs obsidian 旧版 vs 无日期版），裁决优先级：

1. **研究总监整合版 > 单Agent版**（如标注「DDGS搜索后端」的 researcher 版）
2. obsidian 已有版本优先保留（若内容更完整）
3. 字节数大 + 含名称说明/整合标注者更完整

```bash
# 对比方法
md5sum exports/版.md obsidian/版.md   # 相同 = 同内容
diff <(head -50 版A.md) <(head -50 版B.md) | head -40  # 看头部差异判断版本
```

> ⚠️ **蓝之洋案例**：obsidian 原版（研究总监整合版，28429字节）与 exports 新版（DDGS版，28156字节）同日生成但内容不同，保留整合版，DIFF 属预期。

### 第 3 步：统一重命名与收拢散件
```bash
# 重命名 obsidian 已有文件
mv "$DEST/旧名.md" "$DEST/YYYYMMDD_公司简称_客户画像报告.md"
# workspace 根目录散件 → 收拢到 exports（obsidian 已有副本则直接移动）
mv "根目录散件.md" "exports/YYYYMMDD_公司简称_客户画像报告.md"
```

### 第 4 步：生成/更新索引
`README_索引.md` 含：
- 头部说明（目录、命名规范、更新日期、状态管理链接）
- 报告清单表（20+ 行，含**状态列**：`画像` / `🟡 待开发`）
- 说明区（双格式、原厂画像排除、去重记录、新增报告规范）

> ⚠️ 表格一致性：新增状态列后，**所有行都必须有状态值**，否则表格渲染错位。

### 第 5 步：状态标注（无业务往来时）
待开发客户登记到 `待开发客户名单.md`，并在画像报告中双处标注：

```markdown
# 报告头部（无 frontmatter 的报告）
> **合作状态**：🟡 待开发客户（截至 YYYY-MM-DD 尚未与本部门建立业务往来；已登记至 [[待开发客户名单]]）

# frontmatter（有 YAML 头的报告）
---
tags:
  - 待开发客户
status: 待开发客户（截至 YYYY-MM-DD ...）
---
```

## 三、待开发客户名单规范

| 项 | 规范 |
|----|------|
| 登记条件 | 已生成画像，但**尚未与本部门（业务部门）建立业务往来** |
| 名单表 | 客户 / 画像报告(wikilink) / 登记日期 / 状态说明 / 跟进方向 |
| 移出记录表 | 客户 / 登记日期 / 移出日期 / 移出原因（达成首单/试单后移出） |
| 双向链接 | 名单 `[[wikilink]]` → 画像；画像头部反向链接 → 名单 |

> ⚠️ **平台入驻 ≠ 业务往来陷阱（国际交易中心案例）**：我司为创始会员并已入驻其撮合平台，但用户明确该平台身份不等于部门业务往来——**以用户确认的业务往来状态为准，不自动视为已合作**。S级评分（98/110）与待开发状态不矛盾：价值高但尚未产生部门级交易。

## 五、维护规则（新增报告时）

```bash
# 1. 复制到 obsidian 库
cp 新报告.md /data/hermes/obsidian-vault/客户画像/YYYYMMDD_公司简称_客户画像报告.md
# 2. 更新 README_索引.md（新增行 + 状态列）
# 3. 若客户无业务往来 → 登记待开发客户名单 + 画像头部标注
```
