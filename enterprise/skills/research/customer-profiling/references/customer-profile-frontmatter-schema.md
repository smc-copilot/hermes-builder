# 客户画像 L0/L1/L2 frontmatter 规范（NEW，2026-08 实战验证）

> **背景**：2026-08-19 为 obsidian-vault/客户画像/ 全部 20 份画像批量添加 YAML frontmatter，实现"新产品线/新物料 → 客户群机会匹配"的三层检索漏斗。索引文件：`客户画像/FRONTMATTER_索引.md`。
> **核心原则**：frontmatter 与正文**共存**（frontmatter 只做索引/粗筛，全文保留做语义精读兜底），绝不"转换"掉正文。

## 三层检索漏斗

```
新产品线/新物料进入
   ↓
L0 固定属性粗筛（秒级，grep/结构化查询）→ 行业 × 合作状态 × 画像等级
   ↓
L1 品类对照（tags_l1_supplying / tags_l1_opportunity）→ 直接对照新品线品类
   ↓
L2 全文语义精读（LLM 读候选画像全文）→ 具体切入位号、BOM 机会、证据链
```

为什么不是"纯标签"或"纯全文"：
- **纯标签**：封闭集问题——新品线若是标签体系从未枚举的品类（如首次代理 GaN），枚举外命中率为 0；且组合爆炸（每客户 50 字段 × 20 客户 = 1000 值需持续维护，口径不一致就漏）
- **纯全文**：22 份 × ~25KB ≈ 15-20 万 token 每次，慢且贵，大部分 C 级客户不值得精读
- **混合**：标签粗筛省 70-80% token，全文保留做枚举外兜底，三层共同把漏过率压到最低

## frontmatter 字段定义（按 L0/L1/L2 分层）

```yaml
---
title: 蓝之洋科技客户画像报告
company: 蓝之洋科技
type: 客户画像
industry: [电源模组, 消费电子]          # L0 行业（多值列表）
cooperation_status: 已成交              # L0: 已成交 / 已合作 / 待开发
profile_grade: B级 71/110              # L0 等级+分数（必须与画像原文"最终总分"一致）
grade_level: B级                        # L0: S / B / C / 未评级（归一化枚举）
score: 71/110                           # L0 分数（格式 数字/110 或 /100）
tags: [B级, Flash, MCU, 客户画像, 已成交, 电源模组]  # 合并标签（行业+等级+状态+品类）
tags_l1_supplying: >-                   # L1 已在供品类（含品牌映射）
  【待盘点】
tags_l1_opportunity: >-                 # L1 机会品类（含品牌映射，新品线直接对照）
  MOSFET/PMU(贝岭/应能微/士兰微)、MCU(恒烁)、Flash(恒烁)、TVS(应能微)
tags_l2_scenarios:                      # L2 应用场景（多值列表，场景匹配）
  - 充电宝
  - GaN快充
tags_l2_expansion_path: >-              # L2 扩品路径（切入顺序）
  【待盘点】→MOSFET→PMU→MCU→Flash→TVS
updated: 2026-08-19
source: 客户群数据底表(20260810) + 客户画像报告原文
---
```

## 批量迁移工作流（对存量画像）

1. **数据采集**：优先用 `60-Reports/客户群数据底表.md`（18 家已成交的结构化总览：行业/合作实证/画像等级/年采购规模/已在供/扩展机会）——比逐份读全文快；底表没有的客户（如待开发客户）从画像头部提取
2. **脚本批量插入**：写 Python 脚本在文件头插入 frontmatter（`---` 开头 + 原正文完整保留在 `---` 之后）
3. **已有 frontmatter 处理**：文件首行已是 `---` 时**不能覆盖**——保留原字段（title/version/date/author/原 tags/status），将 L0/L1/L2 新字段合并追加到原 frontmatter 内（杉川机器人案例：原 frontmatter 有 version 3.0 + 作者信息 + 7 个 tags，合并后保留全部再补新字段）
4. **YAML 语法验证（强制）**：全部写入后跑 `yaml.safe_load` 校验 20/20 通过，检查必填字段齐全
5. **生成检索索引**：`客户画像/FRONTMATTER_索引.md`——按等级/状态/品类/场景四维速查表 + 新品线匹配使用示例

## ⚠️ 关键陷阱（2026-08 实战全部踩过）

1. **汇总表分数 ≠ 画像原文分数（最严重）**：数据底表是分析产物，其中等级/分数可能与画像原文不符（本次 20 家中 9 家不一致！亿享云底表"中"→原文 B级 61/110；奥视威"中"→原文 B级 69/110；乐橙"中低"→原文 C级 43/110）。**写入 frontmatter 前必须回验每份画像的「最终得分与客户等级判定」节**（grep `最终总分|等级` 定位），以画像原文为准。
2. **score 正则提取陷阱**：从 `profile_grade: B级 71/110` 提取分数时，`re.sub(r"[^0-9]+.*$", "")` 会因"B级"前缀把整个值清空（结果空字符串）。正确做法：`re.search(r"(\d+/\d+)", grade)` 提取。
3. **无分客户处理**：部分画像无量化评分（如"中低"定性表述或未评级），score 留空、grade_level 用归一化枚举（未评级），不要硬造数字。
4. **正文完整性验证**：插入后抽查原文关键章节（如 `评分时间`）仍在，frontmatter 只做前缀不吞正文。
5. **品类标签粒度**：机会品类中 `MOSFET/PMU` 这类复合串会被当作单标签，检索时注意拆词；粒度口径不统一（NOR Flash vs 存储）会造成枚举内漏过——L1 标签尽量用同一品类名词表。

