# 跨销售协同分析方法与案例（Cross-Sales Synergy）

跨销售协同是本 skill 区别于个人级分析的最大增量价值——把分散在各销售手中的画像信息打通，识别并释放上下游/同集团/互补型协同机会。

## 协同类型识别

| 类型 | 识别信号 | 价值 | 处理 |
|------|---------|------|------|
| **上下游协同** | 销售A的客户是销售B客户的供应商/客户 | 产业链绑定、联合拜访、采购决策影响 | 建关联图谱，P0 清单标注跨销售关联 |
| **同集团分散** | 同一集团不同子公司分属不同销售 | 集团总盘议价、统一解决方案 | 评估是否合并归属或协作分成 |
| **多采购部门** | 同一客户多个采购部门对应不同产品线 | 品类扩展空间 | 保留主销售+辅助销售协作模式 |
| **互补产品线** | A 销售客户缺 B 销售主推品类 | 交叉销售机会 | 配对推荐，FAE 协同 |
| **区域/行业互补** | 不同销售覆盖相邻区域或上下游行业 | 信息共享、线索互转 | 建立线索互转机制 |

## 分析流程

1. **构建关联图谱**（阶段一 1c）：客户×销售矩阵 + 上下游关系 + 集团关系
2. **识别高价值协同**：优先看 P0 客户的关联节点（标杆/核心客户的上下游最具价值）
3. **验证可行性**：确认采购决策链、接触人、合作品类是否真实可协同
4. **落到行动**：P0 清单"跨销售关联"字段 + 5c 配对建议 + 5d 行动清单

## 常见陷阱

- **把"协同"当"抢单"**：协同的前提是归属清晰（CRM Owner 为准），辅助销售不改变主归属
- **过度关联**：上下游关系不等于采购协同，需验证接触层与决策链
- **忽视利益分配**：跨销售协同需明确分成机制，否则执行层会抵触

## 案例：电子元器件分销团队

**场景**：销售A（工控）客户"汇川技术"采购 MCU；销售B（新能源）客户"宁德时代"的电池产线设备供应商采购工控板卡。
**关联**：汇川的 MCU 产品在宁德时代产线设备中应用——A 与 B 的客户存在产业链上下游关系。
**协同动作**：A 提供 MCU 技术方案给 B 的客户（设备商），B 引荐 A 接触其客户中的工控采购决策人；FAE 联合支持 2 家客户的产品认证。
**结果**：B 的客户新开 MCU 品类采购（年 300 万），A 通过 B 引荐进入 2 家新能源设备商。

## 量化协同价值

- 协同客户数 = 图谱中有关联关系的客户对
- 协同转化率 = 协同客户中产生新采购/新品类/新引荐的比例
- 协同收入增量 = 协同带来的新品类/新客户收入（建议按季度追踪）
- 建议：每季度复盘协同清单，标记"已转化/进行中/未转化"，转化率 <30% 时检查协同动作是否落地
