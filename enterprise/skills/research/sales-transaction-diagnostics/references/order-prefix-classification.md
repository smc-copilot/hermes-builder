# 订单ID前缀分类参考手册

本文件记录了各种订单编号前缀的识别规则，用于正确区分收入、成本、退货记录。

## 典型多记录模式

同一个物料/订单可能在系统中出现多次：

```
# 模式1: 正常销售 + 成本
CLOUDSZI23030079    +18,513.71  (Revenue - 售价)
CLOUDSZM23040002    +16,383.81  (Cost - 成本)  ← 注意是正数

# 模式2: 正常销售 + 退货
CLOUDSZI23030077    +5,404.62   (Revenue)
CLOUDSZA23040001    -5,404.62   (Return - 退货/冲销)

# 模式3: 同一订单ID分两行，一行收入一行成本
CLOUDSZI23030077    +5,404.62   (Revenue - qty 20,000)
CLOUDSZI23030077    -2,702.31   (Cost - qty 20,000, 负数为成本)
```

## 多轮分析策略

不要追求一次写出完美的分析脚本。推荐**V1→V2迭代模式**：

**V1（快速原型）：**
- 简单按金额分正负
- 输出关键指标（退货率、毛利率）
- 检查指标合理性

**V2（修正分类）：**
- 如退货率>10%或毛利率>70%，说明分类逻辑大概率有误
- 切换到 OrderID 前缀分类逻辑
- 重新计算所有指标

**V3+（深度扩展）：**
- 添加客户集中度帕累托分析
- 销售人效分解
- 隐藏信号检测

## 数据完整性检查

- 若某月份/季度数据量明显偏少，检查是否缺少该期间数据
- 日本实体若无订单号（OrderID为空），按金额汇总即可
- 0元记录（样品/赠品）不影响营收但影响订单数
