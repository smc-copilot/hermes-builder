# 三透镜分析法: 多视角业务诊断框架

## 概述

三透镜分析法是一种**元分析框架**——它不定义"分析什么"（那是`diagnosis-framework.md`的职责），而是定义"如何思考这个分析"。通过强制三个互补的认知视角依次解读同一组数据，确保输出既有量化深度，又有商业敏锐度，还有战略格局。

## 何时使用

- 用户要求"深度分析"、"全面诊断"、"发现隐藏优缺点"
- 数据量超过100行交易记录，有多个交叉维度可挖掘
- 分析结果将用于决策级判断（非简单查询）

## 三透镜定义

### Lens 1: 理科透镜 (Researcher / 量化视角)

**核心任务**: 把原始数据变成可验证的量化结构

| 维度 | 动作 | 输出 |
|------|------|------|
| 财务维 | 逐行解析→P&L汇总→季度趋势→月度曲线 | 销售额/毛利/毛利率趋势表 |
| 客户维 | 帕累托分析→复购率→HHI集中度 | Top N客户占比、客户价值分层 |
| 团队维 | 销售人员业绩→人效比→订单结构 | 销售排名、人均产值、订单分布 |
| 产品维 | 品类→品牌→毛利率分层 | 高/低毛利品类清单 |
| 风控维 | 支付→退货→负毛利→异常扫描 | 风险信号清单 |

**产出特征**: 数字对、排序表、趋势线、百分比。全是"可复现的"——另一个人用同一数据应该得到相同结果。

**行为约束**: 
- 绝不编造数据，缺失值显式标注
- 发现异常数据(毛利率>50%或<-5%)时标记而非抹除
- 计算逻辑透明可追溯

### Lens 2: 文科透镜 (Writer / 商业视角)

**核心任务**: 解读数字背后的商业模式和业务逻辑

**分析焦点**:
- **增长质量**: 增长是来自"做对事"还是"撞大运"？（有机增长 vs 机会性收入）
- **盈利逻辑**: 什么业务真的在赚钱？什么业务只是"看上去在做"？（规模漏斗暴露低毛利业务）
- **客户健康**: 高复购客户做对了什么？流失客户当时漏了什么信号？
- **团队结构**: 团队能力模型是否合理？是否存在单点故障？
- **竞争位**: 这个业务在产业链中处于什么位置？护城河在哪？

**产出特征**: 模式识别、趋势解读、信号归类、商业判断。输出以"发现"和"洞察"为主。

**行为约束**:
- 所有商业判断必须基于Lens 1的量化证据——没有数据支撑的"感觉"是无效的
- 不满足于"正确但平庸"的结论——持续追问"So What?"直到触及本质
- 识别表面数据与真实情况之间的落差(如"销售额高但毛利率极低的业务线是否是伪增长")

### Lens 3: 总监透镜 (Director / 战略视角)

**核心任务**: 冲突裁决 + 创造性综合 + 决策级输出

**三大职能**:

1. **冲突裁决**: 当Lens 1和Lens 2给出矛盾信号时（如"Q4销售额最高但毛利率最低"），总监透镜负责判断哪个信号更本质，给出统一解读
2. **创造性综合**: 将分散的发现缝合为"1+1>2"的战略判断——发现跨维度的因果链（如"独立分销扩张→拉低整体毛利率→利润反而缩水"）
3. **反直觉洞察**: 识别那些"数据支持但直觉以为反"的核心发现——这是总监透镜的最高价值产出

**行为约束**:
- 必须有明确的"反直觉结论"或"So What"升级——没有这个就是聚合而非综合
- 若无法形成反直觉洞察，诚实说明"目前数据不足以支撑深度判断"
- 最终输出必须是决策级的——给出"做什么"的建议，而非仅"是什么"的描述

## 三透镜协同流程

```
Phase 1 [并行]: Lens 1 做量化计算 → 输出结构化数据
                Lens 2 读商业模式 → 输出商业发现
                
Phase 2 [裁决]: Lens 3 接收双方输出 → 标记一致点/矛盾点/盲区
                → 裁决：哪个矛盾更本质？哪个发现更重要？
                
Phase 3 [综合]: Lens 3 缝合分散发现 → 提炼反直觉结论
                → 形成战略建议
                
Phase 4 [验证]: 回查Lens 1数据是否支撑Lens 3结论
                → 若不支撑，退回Phase 2重判
```

## 典型应用场景

### 场景A: 独立分销扩张导致毛利率恶化

```
Lens 1 发现: 独立分销占比从Q1 30%→Q4 60%, 毛利率从18.8%→8.5%
Lens 2 解读: "规模越大赚越少"——这是结构性利润侵蚀
Lens 3 裁决: 这是2024年最核心的战略问题, 高于"增长不够快"
           建议: 做减法 + 重塑业务组合
```

### 场景B: 日本市场终止的连锁影响

```
Lens 1: 日本贡献23%营收、23.5%毛利率 → 流失导致全年利润缺口
Lens 2: 日本是"总部资源型业务"而非自营获客, 不可复制
Lens 3: 真正损失不是$18.6万营收, 而是失去一个高利润品类，
        为了弥补, 不得不在低毛利独立分销上做更多——恶性循环
        建议: 不试图找回日本客户, 而是培养授权分销高毛利品类
```

## 常见陷阱

### 陷阱1: Lens 1 未完成就进入 Lens 2
**表现**: 数据还没清洗完就开始做商业判断, 用"感觉"替代"数字"
**规避**: Lens 1 的量化计算必须全部完成并验证合理性后, 才能进入 Lens 2

### 陷阱2: Lens 3 没有反直觉结论
**表现**: 只是重复了Lens 1和Lens 2的发现, 没有"超出原始数据"的新洞察
**规避**: 写结论前问自己——"这个结论用户看了会意外吗？如果不会, 说明还不够深"

### 陷阱3: 三透镜变成三人"分头写报告"
**表现**: 三份独立的分析文档被拼接在一起, 没有真正的对话和裁决
**规避**: Lens 3 必须显式标注"一致点/矛盾点/裁决依据", 而非简单的"以下为综合"

### 陷阱4: 数据嵌入效率低导致分析放弃
**表现**: 试图用TSV文件或heredoc嵌入456行数据, 失败后放弃量化分析
**规避**: 使用紧凑元组格式嵌入数据, 见下文"数据嵌入技术"

## 配套数据嵌入技术: 紧凑元组格式

当原始数据体量超过50行且嵌入在对话上下文而非文件中时, 使用紧凑元组格式替代TSV heredoc:

```python
# 每行: (销售额, 毛利, 类型代码)
q1 = [(10.60, 1, '电商'), (306.65, 48, '电商'), (5096.68, 438, '电商'),
      (40331.53, 12146.23, '日本')]
q2 = [(29888.08, 4148, '独立'), (406.97, 92, '电商'), ...]

# 类型代码: '电商'=自营电商, '独立'=独立分销, '日本'=日本市场, '授权'=授权分销
```

**优点**: 
- 节省>60%字符数（无需重复季度/客户/物料等分析不需要的字段）
- 可直接嵌入Python脚本, 无需读写文件
- 便于按季度/客户/类型拆分聚合

**何时使用**: 数据来自用户对话消息（非文件附件）, 且分析聚焦在财务与结构维度而非单个订单明细。
**何时不用**: 需要逐行展示原始数据, 或分析粒度要求到订单/物料级别。
