# Sales Transaction Diagnostics 企业销售业务数据诊断分析

## Trigger Conditions

当用户提供**原始交易级业务数据**（非已汇总报表），并要求进行业务分析时触发。典型数据特征：

- 包含多列字段：季度/月份、订单号、客户、销售、产品、数量、金额
- 混合了不同性质的记录：正数金额（收入）和负数金额（成本/退货/冲销/跨部门分摊）
- 通常是文本格式（TSV/CSV），需要逐行解析
- 数据量通常在50-500行之间

**不适用的情况：** 用户已提供汇总好的财务报表、KPI仪表盘截图，或仅需要单一维度的查询。

## ⚠️ 数据上下文确认（Phase 0，解析前必做）

在开始解析数据前，必须先确认以下上下文——**跳过这一步是90%分析错误的根源：**

### 1. 币种确认
- 询问：\"这些金额是人民币还是美元？含税还是不含税？\"
- **电子元器件分销行业惯例是美元、不含税**——不要假设是人民币
- 报告中所有金额须标注币种，可附人民币换算参考（用当年平均汇率~7.1）

### 2. 业绩归属确认
- 询问：\"联合完成的大客户/机会性订单如何归属销售人员？\"
- **表面数据可能严重误导**：一个处理30单小单的销售可能隐藏着战略客户关系贡献
- 必须显式询问是否有\"协作业绩\"\"跨部门分摊\"等归属规则

### 3. 记录性质确认
- 询问：\"数据中的负数金额是什么含义？——是成本扣减？退货？还是跨部门业绩分摊？\"
- **不要假设负数=退货**。在分销业务中，负数可能是成本、冲销、或者与其他部门的收入分成
- 如果事前不确定，在第一次分析后先验证退货率和毛利率的合理性

### 4. 业务模式确认
- 询问：\"这是B2B还是B2C业务？\"
- **B2B的评估标准与B2C完全不同**（详见下方Pitfalls）

## Standard Workflow

### Phase 1: 数据加载与结构识别

1. 将数据保存为文件 → 确定分隔符（Tab/Comma/Space）
2. 识别所有字段列及其含义
3. 确认数据范围：时间跨度、包含哪些主体/部门
4. 如果不是单一部门数据，按部门/业务组进行拆分

### Phase 2: 记录分类（关键步骤 ⚠️）

这是最容易出错的步骤，必须正确区分四种记录类型——**误分类会让退货率虚高、毛利率失真**：

```
收入记录 (Revenue)          = 正数金额的订单
成本记录 (Cost)             = 负数金额的订单（或通过特殊OrderID前缀识别）
退货/冲销 (Return)           = 退货单/红字冲销（通常有特殊前缀如 CLOUDSZA, CLOUDSZR, 104AC）
跨部门分摊 (Revenue Sharing) = 业绩分成/订单扣减（不是退货，不是成本——是内部协作分配）
```

**分类依据优先级：**
1. **OrderID 前缀规则**（最可靠）：
   - `CLOUDSZA`, `CLOUDSZR`, `104AC` → 退货
   - `CLOUDSZM` → 成本分录（独立成本记录）
   - `CLOUDSZI`, `CLOUDHKI`, `104IN`, `102IN` 等 → 正常销售
   - 同一OrderID下可能出现多次（一次正数收入、一次负数成本）
2. **金额符号**（辅助规则）：
   - 正常销售单号下，正数 = 收入，负数 = 成本
3. **数据理解**：不同前缀通常代表不同系统模块（销售→财务→库存）

**常见陷阱：** 将成本记录误归类为退货（导致退货率虚高）；或将跨部门分摊误归为成本（影响毛利计算）

### Phase 3: 多维分析框架

按以下维度依次展开，每个维度生成量化数据：

```
┌─ 财务维 ──────  P&L概览 → 季度趋势 → 月度趋势
├─ 客户维 ──────  帕累托分析 → 复购分析 → 价值分层 → 增长/流失信号
├─ 团队维 ──────  销售人员业绩 → 人效 → 客单价 → 订单结构
├─ 产品维 ──────  品类分析 → 热销品 → 毛利率 (已知vs估算)
├─ 风控维 ──────  支付方式 → 信用销售 → 退货率 → 客户集中度
└─ 隐藏信号 ────  增长型客户 → 流失预警 → 异常模式
```

### Phase 4: 特殊场景处理

**场景A：成本数据不完整**
- 部分订单有成本数据（同一订单出现两次：销售价 + 成本价）
- 部分仅有销售价（授权业务，成本保密）
- 处理策略：对已知成本订单计算实际毛利率，未知部分用用户给出的估算毛利率（如17%），计算综合毛利率

**场景B：多实体/多部门混合**
- 按 Department 和 DeptGroup 字段拆分
- 日本实体（海外子公司）通常独立核算，可单独分析
- 标明哪些是非线上获客业务（授权/总部指派客户）

**场景C：负数金额的多种含义**
- 需要区分：正常销售的成本、退货单、冲销单、价格调整、跨部门分摊
- 同样以 OrderID 前缀为最可靠依据
- **如不确认负数含义，在Phase 0直接问用户**

**场景D：机会性收入与有机增长的分离（B2B特有 ⭐）**
B2B业务中经常混入机会性大单（如总部分配的大客户、跨境机遇订单），必须从核心业务中分离：
- **机会性收入特征：** 单一客户一次性大额、无复购、非线上获客来源、需要特殊渠道/关系
- **有机增长特征：** 线上获客、逐步放量、复购可预期、模式可复制
- **处理策略：** 先计算含机会性的总业绩（给管理层看），再计算剔除后的核心有机增长（给运营层看）
- **叙事影响：** 机会性收入剔除后，团队的真实成长曲线可能更陡峭（如从Q2 $61K到Q4 $286K，+369%）

### Phase 5: 战略洞察输出

基于数据分析结果，输出结构化诊断报告：

1. **评分卡**：营收增长、客户质量、团队成熟度、产品结构、风控水平
2. **隐藏优点**：反直觉的好信号（如高复购率、品类扩展、爆发式增长）
3. **结构性缺点**：集中度风险、人效分化、单一客户依赖、长尾薄弱
4. **成长潜力**：增长型客户、可复制模式、大单转化能力
5. **破局建议**：可操作的1-3个战略方向（如"H型双轨策略"）

#### 客户质量分级体系 (Customer Quality Grading)

在完成客户集中度和毛利率分析后，按 **毛利率 × 交易活跃度** 双维度将客户分为四级：

| 等级 | 条件 | 特征 | 管理策略 |
|------|------|------|----------|
| A级 | 毛利率>15% + 交易≥3次 | 高利润、高粘性 | 重点维护、FEI资源倾斜 |
| B级 | 毛利率10-15% + 稳定交易 | 中等利润、潜力股 | 标准维护、引导迁移 |
| C级 | 毛利率<10% + 高频交易 | 高营收但利润薄 | 评估真实盈利能力 |
| D级 | 单次交易/低价值/样品单 | 未转化或询价 | 自动化服务模板 |

**反直觉洞察（"伪繁荣"模式）：**
销售额最高的客户往往是毛利率最低的客户。需为每个C级客户做**客户盈利能力复盘**（含人天成本分摊），识别占用大量人力却几乎不贡献利润的"伪繁荣"客户。

#### 战略框架模板

**SWOT矩阵：** 四象限分析（优势/劣势/机会/威胁），含量化数据支撑。

**风险预警清单：**

| 编号 | 风险项 | 严重度 | 状态 | 描述 | 应对策略 |
|------|--------|--------|------|------|----------|
| R1 | [风险名] | 极高/高/中/低 | 当前/潜在 | [量化描述] | [具体策略] |

**三阶段战略优先级：** 即刻行动(0-3月)→短期(3-6月)→中期(6-12月)

### Phase 6: 正负分摊记录处理（分单业务专用 ⚠️）

当数据中包含**正数（真实销售）和负数（跨部门业绩分摊）** 的混合记录时，必须按以下规则处理：

**数据分类规则：**
```
真实销售 (Gross Sales)  = 销售额 > 0 的所有记录 → 用于计算Gross Revenue和Gross Margin
跨部门分摊 (Split/Deduction) = 销售额 < 0 且无成本的记录 → 用于计算NET Revenue
成本分录 = 销售额 < 0 且有成本的记录 → 同单号的成本补录（与正数记录配对）
退货 = 特定前缀（CLOUDSZA/CLOUDSZR/104AC）
```

**NET vs GROSS 双重计算：**
```
Gross Revenue = SUM(正数销售额)           → 衡量规模和市场地位
NET Revenue   = SUM(正数 + 负数销售额)     → 衡量实际归属该部门的收入
Gross AttrGP  = SUM(正数归属毛利)          → 表面的毛利润贡献
NET AttrGP    = SUM(全部记录归属毛利)       → 扣除分摊后的真实毛利润
分摊率 = (Gross - NET) / Gross × 100%     → 跨部门协作的成本占比
```

**关键洞察：**
- 分摊率 > 20% 说明该部门大量依赖跨部门协作，独立盈利能力被高估
- 分摊主要发生在"独立分销采购+电商销售"的业务模式中
- 日本海外子公司的正负抵消后在主表显示为0，须单独分析

## Pitfalls

### ⚠️ 致命级：CSV字段中含逗号（电子元器件物料代码常见）
电子元器件行业原始交易数据中，物料代码（Material Code/Part Number）常含逗号（如 `74HC00D,653`、`CPC1117NTR`、`LM2596SX-ADJ/NOPB`），导致标准CSV解析将物料代码拆分为多个字段，整行字段数超过预期列数。

**规避策略（从右到左装配法）：**
1. 先按逗号分割获取原始字段列表 `parts = line.split(',')`
2. 如果 `len(parts) == 列数` → 正常解析
3. 如果 `len(parts) > 列数` → 从右向左提取末尾固定字段（业务类型、毛利、采购员、销售额、数量），剩余中间字段就是含逗号的物料代码：
```python
biz_type = parts[-1]      # 最后一个字段是业务类型
gross_profit = parts[-2]   # 倒数第二是归属毛利
purchaser = parts[-3]      # 倒数第三是采购员
sales_amount = parts[-4]   # 倒数第四是销售额
qty = parts[-5]            # 倒数第五是数量
# 从 parts[5] 到 parts[-6] 是用逗号连接的完整物料代码
material_code = ','.join(parts[5:-5])
```
4. **适用场景：** 用户直接从ERP导出的CSV、BOM表、采购明细表等电子行业原始数据

### ⚠️ 致命级：数据分类错误
第一次运行时很容易将成本误判为退货。必须先验证退货率和毛利率的合理性：
- 退货率 > 5% → 大概率是分类逻辑错了（分销行业退货率通常1-3%）
- 毛利率 > 70% → 大概率成本数据不完整（纯分销30-50%，授权分销15-25%）
- 发现不合理后，重新审视负数金额的含义，与用户确认后再迭代

### ⚠️ 致命级：B2B vs B2C 基准混淆
这是本技能最常出错的地方。**B2B业务的评估标准与B2C完全不同：**

| 指标 | B2C标准 | B2B正确标准 | 本次会话的经验教训 |
|------|---------|------------|-------------------|
| 复购率 | 30-40%=优秀 | 成熟分销**70-85%**，初创第二年**60-65%** | 56%在B2C是优秀，在B2B是**需关注** |
| 一次性客户 | 60-70%=正常 | **<40%**为健康（剔除样品询价单后） | 需区分<100的样品单和真正的流失客户 |
| 退货率 | <5%=正常 | <3%=优秀（分销行业实际退货极低） | 遇>5%先检查分类逻辑 |
| 客单价 | 取决于品类 | 分销B2B通常在$1K-$20K | 样品/开发板单<$100不应计入大客户分析 |

**处理方法：** 在Phase 0确认业务模式后，直接使用B2B基准进行评估。报告中应显式注明所用基准。

### ⚠️ 重要级：表面数据悖论（Salesperson Surface Data Paradox）
销售人员业绩分析时，**纯靠订单金额汇总可能严重误导**：
- 大量小单（30单/$23K）的销售可能隐藏着战略客户关系贡献（+$106K）
- 一个人完成的机会性大单可能被归到另一个人的名下（协作/分配规则）
- **处理方法：** 必须与用户确认业绩归属规则后再下结论

### 普通级：其他注意事项
1. **日本/海外业务需单独审视**：通常这些是总部授权业务或机会性订单，销售不直接参与线上获客，应剔除后计算核心业绩
2. **机会性收入 vs 有机增长**：必须分离一次性大单（如日本业务$212K）和可复制的销售模型增长
3. **单价为零的记录**：样品/赠品/工具单（价格为0），不应计入营收但会影响订单数统计
4. **订单ID重复出现**：同一订单号可能出现3-4次（收入/成本/退货/分摊），必须按类型分别汇总
5. **数据缺失判断**：如果Q3/Q4数据明显少于Q1/Q2，检查数据是否完整，而非直接下结论说业务收缩

## Verification Steps

运行分析后检查以下合理性指标（**B2B基准**）：

| 指标 | 合理范围 | 异常判断 | 异常时的可能原因 |
|------|----------|----------|-----------------|
| 跨部门分摊率 | 0-5% | >5% | 协作业务多，需确认分配规则 |
| 毛利率（已知成本） | 30-50%（纯分销） | >70% | 成本数据不完整 |
| 综合毛利率 | 15-40% | >50% | 缺失成本未补全估算 |
| 订单均价 | $1K-$20K | <$500 | 样品单过多，需分层统计 |
| 月均活跃客户数 | 20-50家（第二年） | <10 | 数据可能缺失 |
| 销售人效差距 | <5倍为健康 | >10倍 | 可能有"帮忙接单"或归属规则问题 |
