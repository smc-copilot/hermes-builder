# b 表（行业→芯片品类）维护方法论

> 2026-08-24 实战沉淀：b 表 20→38 行业扩充（v1.1.0）+ 38 行芯片品类全量完善（v1.2.0，双 Agent 交叉审查）。
> 本文件是"如何做 b 表大版本维护"的操作手册，与 SKILL.md「维护规范」互补（后者管流程与纪律，本文件管方法、锚点与坑）。

## 一、行业分类框架检索锚点（扩充"还有哪些行业用芯片"时）

用四类锚点交叉验证，不要只靠直觉：

| 锚点 | 内容 | 用法 |
|------|------|------|
| WSTS/SIA 终端市场框架 | 通信、计算机、消费电子、汽车、工业、政府/军工/航天 | 对照是否漏了军工航天、手机（通信大头）等大域 |
| 国标 GB/T 4754-2017 C39 | 计算机/通信设备/广播电视/雷达/智能消费设备（无人飞行器、服务机器人）/电子器件制造等 9 个中类 | 支撑无人机、服务器/数据中心、商用终端、教育电子等细分 |
| 行业报告口径 | 功率半导体下游（工业 25.4%/汽车 25.3%/消费 23.6%）、元器件七大下游（消费/工控/车规/AI服务器/医疗/能源/通信） | 验证服务器、医疗设备等是否值得单列 |
| 客户画像 frontmatter 索引 | obsidian-vault/客户画像/FRONTMATTER_索引.md 的 L2 tags_l2_scenarios | 我方真实客户已覆盖的行业 = 缺漏的直接证据（实战：辰浩=医疗、蓝之洋=储能、乐橙=ONU、中德=门禁，原 b 表全缺） |

## 二、扩充规则（向后兼容）

1. **原行不动**：已有行内容与编号一律保留，新行业追加编号（20→21…38）。下游 skill 按编号/名称引用，重排会破坏引用。
2. **粒度一致**：新行业采用与原表相同的"终端产品形态"粒度（有厨电/小家电/清洁电器这种细粒度先例，手机、TWS、VR/AR 就应单列而非并进"消费电子"大类）。
3. **宽概念拆分而非合并**："智能硬件"太宽时按 BOM 差异拆类（智能音频/VR-AR/智能家居/新兴消费各成一类），合并会失真。
4. **用「行业范围说明」表处理重叠**：相近子领域（充电桩→新能源、ONU/光模块→网络设备、机器视觉→摄像头类、门禁→安防、车联网后装→汽车电子、PC/笔电→IT设备、商显→显示设备）写进范围说明小节，不重复建类。
5. **每个新增行业给出完整芯片清单**：延续原表风格（中文顿号分隔），按 主控/存储/电源/模拟/接口/功率/传感/连接 框架。

## 三、芯片品类全量完善：双 Agent LITE 分派 + 总监融合

对全表逐行做"品类是否齐全"审查时，用 perspective-decomposer LITE 模式分两个非冗余视角并行：

- **视角A → researcher（技术 BOM 完整性）**：按全维度审查并产出完整清单。审查维度：主控计算、存储、电源管理、模拟信号链、接口连接、功率器件、传感器、保护器件、时钟、逻辑、射频无线、显示、电机驱动、继电器/光耦、隔离器、天线、连接器、无源配套、散热。
- **视角B → writer-zh（分销商业实战）**：补充"实际客户会采购但技术清单容易漏"的品类，锚定真实客户案例（TWS/穿戴客户采微型电芯+无线充+触控IC；ONU 客户采网络变压器+天线；储能客户采 GaN+电芯+无线充+变压器；扫地机客户采 IMU+激光雷达+多路马达）。

**总监融合裁决规则（实证优先）**：
1. 技术视角补全 → 全量吸收（除非明显错误）
2. 商业视角补充 → 只吸收**电子元器件级**品类（锂电电芯、扬声器/麦克风、蜂鸣器、红外接收头、网络变压器、电流互感器、NTC、压敏电阻、熔断器、触控IC、Type-C/PD、SIM卡座等）；**剔除结构/光学级部件**（散热器、光波导、螺旋桨、屏蔽罩、铝基板、导热材料）——超出"电子元器件"定位（散热风扇除外，原表已有先例）
3. 原清单所有项必须保留（含 NVR/DVR、显示面板、整流桥、滤波电容等非芯片项，维持原文粒度）
4. **双 Agent 独立命中的品类 = 高置信必收**（实战命中：TVS/ESD、晶振/时钟、充电管理、栅极驱动、隔离器、存储、连接器/FPC）

## 四、高频遗漏品类速查（"通用 BOM 底座"）

几乎所有行业都容易漏以下品类，审查时优先检查：
TVS/ESD保护器件、时钟芯片/晶振、存储芯片（Flash/DDR/eMMC/EEPROM）、充电管理、LDO/DC-DC、栅极驱动、隔离器、连接器/FPC、保险丝/熔断器、运放/比较器、ADC/DAC、电平转换、天线、锂电电芯。

行业指纹品类（识别客户归属、深度方案绑定用）：
医疗=模拟前端/隔离电源；储能=BMS AFE/熔断器；服务器=Redriver/BMC；基站=PA/双工器；智能电表=计量芯片/电流互感器；汽车=车规连接器/CAN-LIN收发器。

## 五、版本纪律

- 大版本更新按数据资产「维护规范」：frontmatter version + 变更记录表同步 +1，注明变更范围与依据（改了什么表、依据来源）。
- 本次实战：v1.0.0（初始）→ v1.1.0（20→38 行业）→ v1.2.0（38 行品类全量完善）。
- 中间产物（子 Agent 输出、共享快照）可存档 exports/ 备查，但权威数据只以 SKILL.md 为准。
