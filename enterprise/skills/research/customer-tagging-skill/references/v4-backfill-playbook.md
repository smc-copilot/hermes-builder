# Schema 版本升级回填 Playbook（v3.0→v4.0 实测沉淀 2026-08-20）

> 适用范围：skill 框架版本升级（如 v3.0→v4.0 新增 D1.6/D2.6 分类）后，对**已入库对象**做增量回填，不重打已有标签。
> 实测：20 个对象、515→593 条标签（+78）、库版本 v1.1→v2.0（结构变动 X+1）、字典 36→40 条。
> 与 `batch-tagging-playbook.md` 的关系：那是「首次批量打标签」，本文件是「schema 变更后的存量升级」。

## 0. 回填前的全局检查

- 确认 skill 新版本已定稿（SKILL.md version 字段）；确认新框架对完整性评分/配额/枚举的影响：
  - 完整性 Σ 变化（v3.0 客户模式 Σ=24 → v4.0 Σ=26.5，新增 D1.6 权重 1.0 + D2.6 权重 1.5）；
  - 配额变化（COVERED ≤40 → ≤46，其中 D1.6 ≤8、D2.6 ≤8）；
  - 新增 coverage_status 枚举（COVERED_WITH_INFERENCE ≤0.7）。
- 读取 `客户标签库.json` 确认现版本与对象清单；读取全部对象中间 JSON（`exports/tag_objects/`）。
- **关键决策：哪些对象产新增标签、哪些按红线不产**——本轮 18/20 产 D2.6 倒推标签，2 个不产：
  - 九十九度光电：产品方向画像自标【推测】→ D1.6 产品线清单照列（COVERED_WITH_HEURISTICS），**D2.6 不产**（无 COVERED 实证产品，进候选池）——展示体系纪律而非硬凑；
  - 国际交易中心：平台型交易服务（无终端产品）→ D2.6 明确标"不适用"，不产倒推。

## 1. 素材提取（D1.6 产品线清单的输入）

- 用 Python 批量抽取每份画像「## 二、核心技术与产品/服务」章节（正则 `## 二、.*?(?=\n## 三、)`），输出产品线概览表格行。
- 注意章节目录差异：杉川画像该章节是「授权品牌清单」而非产品线表（ODM 大厂特征），需从文本判断产品形态；国际交易中心是「三大交易模式+四大增值服务」服务型描述。
- 产品记录字段：名称/品类归属/是否自研/状态（规划/研发/试产/量产）/说明。自研字段画像常写「推测是」→ 保留原词。
- **证据分级**：画像产品线概览表明确列出 → COVERED（conf 0.7）；仅经营范围推断（佳帝/乐橙）→ COVERED_WITH_HEURISTICS（conf 0.6 + PENDING_CONFIRM）。

## 2. 增量标签生成（脚本模式：EXTRAS dict + 追加）

- 每个对象在脚本内维护一个 EXTRAS dict：products / services / tech / inference（每条含 source_product、chip_category、inference_basis）。
- **tag_id 连续性（易错）**：从对象现有 tags 计算 `max(int(tag_id.split('-')[1]) for t if startswith('D1-'))`，新标签序号 = max+1 递增；**不要从 001 重排**（会与既有标签冲突、破坏跨对象引用）。
- **source_report_id 陷阱（本轮实际踩坑）**：新标签的 `source_report_id` 必须复用对象现有标签的值（画像报告文件名，如 `20260807_奥视威_客户画像报告.md`），**不是** `obj['report_date']`（那是生成日期）——用 `obj['tags'][0].get('source_report_id','')` 取出复用。
- 追加后更新 `obj['skill_version'] = '4.0'`。
- **完整性评分重算公式**（Σ 基准变化，不能直接沿用旧分）：
  `old_sigma = old_comp / 100 × 旧Σ`；`new_sigma = old_sigma + D1.6权重(1.0) + D2.6权重(1.5，仅当产倒推标签)`；`new_comp = round(new_sigma / 新Σ × 100)`。
  实测效果：v3.0 的 68-83 分重算为 v4.0 的 65-85——分母变大导致普遍略降，属正常语义（更多分类更难满分），不必回滚。

## 3. 合并入库（结构变动版本规则）

1. 校验全部中间 JSON（skill_version=4.0、每标签有 quality/confidence）；
2. 重读最新库 → 按 object_id 整体替换 tags[]；
3. **schema.dimensions 更新**（v4.0 改为 `["D0 撮合门控","D1 静态属性(含D1.6产品与服务体系)","D2 技术需求(含D2.6产品→芯片倒推)",...]`）；
4. 字典扩展（新 tag_name_cn：产品线清单/服务模式/核心产品技术特征/芯片需求倒推清单）；
5. **版本号：结构变动 → X+1（v1.1→v2.0），不是 Y+1**——新分类/新枚举/新维度文案均属结构变动；
6. changelog 记一条（trigger=skill 版本升级后批量回填，reason=用户需求）；
7. 写回 `ensure_ascii=False, indent=2`。

## 4. MD 报告重生成

- 删除旧版 `20260820_*_客户标签报告.md` 后全量重生成（覆盖而非追加）。
- 报告生成器需处理**ARRAY 标签的 JSON payload 美化**：`tag_value_actual` 以 `[` 开头时 `json.loads` 后按语义渲染——
  - 产品线清单 → `名称（品类｜自研:x｜状态）——说明`；
  - 芯片需求倒推清单 → `来源产品 → 品类[STRONG]`。
- 概览新增一行「v4.0 倒推标签：N 条」；撮合建议第八节拆「实证品类」与「倒推品类机会清单（待 FAE 验证转正）」两栏。

## 5. 终验清单

- 库版本 = X+1；对象数不变；标签总数 = 旧数 + 新增数（本轮 515+78=593）；
- 每对象 D1.6 标签数 = 3（产品线清单/服务模式/核心产品技术特征）；D2.6 倒推标签 ≤8 配额；
- coverage_status 分布出现新枚举（本轮 18 条 COVERED_WITH_INFERENCE）；
- object_id 唯一、对象内 tag_id 唯一；
- 抽查 1 份高完整度报告（如 AOSHIWEI 85 分）确认 ARRAY 渲染与两栏撮合建议格式。

## 6. 回填的质量纪律（与首次打标签一致 + 新增）

- 倒推品类词必须对齐授权产品线 c 表（RS485/CAN总线、存储(NOR Flash)、PMU…），不允许自造品类词；
- 倒推优先引用画像内「产品-芯片匹配表/历史采购料号实证」互证（如奥视威倒推 HDMI/PMU ↔ 历史订单 IT66121/IP2716）；
- 平台型/纯软件/服务型客户禁止倒推芯片标签（无产品实证 → 标"不适用"）；
- 倒推 conf 上限 0.7（COVERED_WITH_INFERENCE）；经营范围推断产品的倒推降到 0.6 + PENDING_CONFIRM；
- 回填脚本（EXTRAS dict 模式）保留为可复用脚本：`exports/v40_backfill.py`（下次升级改 EXTRAS 即可）。
