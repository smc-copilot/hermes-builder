## Decisions Closed This Grill (Q1–Q24)

### 命令与状态机

- `--initialize`：收敛到 READY。venv 门通过则跳过 uv，从第一个失败阶段继续。从未初始化则全量 Init。同一身份 READY 则只校验。GUI「重试」走此命令。
- `--repair`：占用检查通过后 T0 改名并重建 Generated（即使 CLI 当前能跑）。GUI「重建运行时」走此命令。
- 跳过 `UV_SYNC` 当且仅当活路径 `venv\Scripts\hermes.exe` 存在，且 `import yaml, openai` 与 `hermes.exe --version` 均满足 Agent `0.21.0`。失败备份树不得当活 venv。
- 成功提交顺序唯一：`UV_SYNC → IMPORT_VERIFY → CLI_VERIFY_VENV → SKILLS_MERGE → ENV_APPLY → CLI_STAGE_BIN → CLI_VERIFY_BIN → RECEIPT_COMMIT`。
- receipt 发布前失败补偿：保留 venv；`bin\hermes*.exe` 回到 T0（新装则删除本次 copy）；撤销本次受管 Skill 与本次未改字节的 `CreateNew` 模板；本次已写出的 HKCU 滚 T0。未 READY 不得让桌面契约路径可启动。
- `--purge-generated-runtime` 不存在。

### `--status`（零写入）

| `runtimeState` | 退出码 | 含义 |
|---|---|---|
| `READY` | 0 | receipt 有效且观测匹配 |
| `ABSENT` | 20 | MSI 未注册 |
| `PAYLOAD_INSTALLED` | 21 | 已注册，从未成功 Init，也无失败 Generated 记录 |
| `REPAIR_REQUIRED` | 22 | Generated 失败或 receipt/观测漂移 |
| `INTERRUPTED` | 23 | 锁在、holder PID 已死；`errorCode=ENGINE_INTERRUPTED` |
| `INITIALIZING` | 24 | 锁在、holder PID 仍活 |
| `PAYLOAD_INSTALLED_REBOOT_REQUIRED` | 25 | HermesRoot 仍有待替换文件 / RM reboot-required |

Receipt 的 `runtimeState` 仍只能是 `READY`。上述枚举只属于探针。

零 mutation 阻断（占用、磁盘、身份、重启）**不**把 `PAYLOAD_INSTALLED`/`READY` 升成 `REPAIR_REQUIRED`；`--initialize` 仍可写 operation record 与诊断。

### `--initialize` / `--repair` 退出码

| 结果 | 退出码 |
|---|---|
| READY | 0 |
| ABSENT | 20 |
| `INSTALL_BUSY` | 24 |
| `REBOOT_REQUIRED` | 25 |
| 其他失败 | 1 + stdout 单行 JSON envelope |

`--quiet` 同样打这一行 JSON。`UV_SYNC_FAILED` 只在随包 `uv.exe` 已启动且退出码非 0 时使用。对 venv / `bin\hermes*.exe` 的 rename/delete/overwrite 遇到 access denied 或 sharing violation → `RUNTIME_IN_USE`。

### 锁

- 路径：`%LOCALAPPDATA%\hermes\state\runtime-init.lock`（`operationId` + pid + exe + `startedAtUtc`）。
- 无墙钟超时。PID 活且 exe 匹配 → `INSTALL_BUSY`。PID 死 → 探针报 `INTERRUPTED`。
- `--status` 绝不创建/替换/删除该锁。`--initialize`/`--repair` 在 PID 死或 exe 不匹配时用新 `operationId` 替换后继续。

### 占用与升级预检

- Setup 启动 `msiexec` 之前、Init 第一次 Generated mutation 之前，同一套 holder 扫描。命中 → `RUNTIME_IN_USE`，不启动 msiexec、不改 venv。
- `3010`：包装脚本不得调用 Init。Init 自己认 HermesRoot 待替换文件，不把「机器任意待重启」当阻断。

### 失败树、磁盘、导出

- 失败半成品 → `state\runtime-backups\<op>\`。默认只留最近一次失败树；`RUNTIME_ROLLBACK_FAILED` 除外，须人工确认后才删。
- `--repair` 峰值磁盘：`2 * venvEstimatedBytes + 512MiB`；首次建 venv：`1 * venvEstimatedBytes + 512MiB`；跳过 uv：`512MiB`。Setup 前公式 `max(8GiB, ceil(1.5*(uncompressedPayloadBytes+venvEstimatedBytes)))` 保留。
- READY 且 receipt 已发布后，删除**本次成功**的 T0。`--status` 不删任何备份。
- `uncompressedPayloadBytes` 必须写入 `release-manifest-v2.json`，等于已签名 runtime-manifest 文件 size 之和，且 `>0`。对不上则构建失败。
- `--export-diagnostics`：复制 InstallerLogs（默认最近一次，或 `--operation-id`）、receipt、operation record、skill ledger、redacted 诊断。禁止 venv、runtime-backups、`.env` 原文、sessions/memories。目标目录已存在且非空 → `EXPORT_TARGET_NOT_EMPTY`。

### Skills / 迁移

- Ledger：`%LOCALAPPDATA%\hermes\state\enterprise-skill-ledger-v2.json`，Init 原子替换，非 USER_OWNED，卸载 MSI 不删。
- 不为 Cleanup 条件单发 v1 补丁 SKU。发布门仍是对实际分发的 0.21.0 MSI 做 Win10 升级真机断言。仅 USER_OWNED 字节变化才 `MIGRATION_BLOCKED`。旧 Cleanup 若误删 venv，视为可重建。
